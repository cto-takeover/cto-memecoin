# Deploy runbook (spec 6, Fri Nov 13)

This runbook deploys both coins, seeds the main coin, and records the proof. It is for the human who holds the testnet keys.

`node scripts/deploy.mjs` writes this file from `reference/constants.json`. Do not edit this file by hand.

**Prerequisites:**

- near-cli-rs 0.31.1 (the version from spec 0), `jq`, and `openssl`.
- The full-access keys in `~/.near-credentials/`. Keys stay there and in Vercel. Do not put keys into git.
- An account of your own that pays for top-ups. This account has no power over the coins. Set it:
  ```bash
  export ME=<your-account>.testnet
  ```

Committed `res/cto.wasm`: SHA-256 `5a7b0e9bae929bdc0c1533b02b8c8e0a02b13c30514bbee9f932ccdc565850b8`, NEAR code hash `76CXTQ95QnsyK32R4wCP2FVJuxEngaD1U7aZYnrzK8gf`. Docker is not available on the build machine, so this is a `non-reproducible-wasm` build. The README tells readers this. `npm run verify` compares the deployed code hash with this file.

## 1. Check the wasm

1. Get the latest code and install the dependencies:
   ```bash
   git pull && npm ci && npm --prefix web ci
   ```
2. Run the checks:
   ```bash
   npm run verify
   ```
   Expected: the Rust lines show PASS. The live lines show SKIP, because the coins are not deployed yet.

## 2. Check the accounts

`spike/RUN.md` created cto.testnet, demo-cto.testnet, ani-cto.testnet and budi-cto.testnet with the faucet on Nov 10. Each account got 10 NEAR and one full-access key. The keys are in your legacy keychain.

1. Make sure that each account has exactly one key and no code:
   ```bash
   for a in cto.testnet demo-cto.testnet ani-cto.testnet budi-cto.testnet; do
     ls ~/.near-credentials/testnet/$a.json && near account list-keys $a network-config testnet now
   done
   ```
   If a key file is missing, the account cannot deploy. Stop and tell Claude.
2. Send 10 NEAR to ani and to budi, so each has 20 NEAR. Each takeover attaches 0.25 NEAR for the voice key.
   ```bash
   for a in ani-cto.testnet budi-cto.testnet; do
     near tokens $ME send-near $a '10 NEAR' network-config testnet sign-with-legacy-keychain send
   done
   ```

## 3. Deploy both coins

### Main coin: `cto.testnet`

1. Deploy the code and call `new` in one transaction. The temporary key signs it:
   ```bash
   near contract deploy cto.testnet use-file res/cto.wasm \
     with-init-call new json-args '{"name":"CTO","symbol":"CTO","opening_price":"1000000000000000000000000","decay_delay_s":604800,"decay_length_s":604800,"faucet_amount":"2000000000000000000000000","allocations":[]}' \
     prepaid-gas '100 Tgas' attached-deposit '0 NEAR' \
     network-config testnet sign-with-legacy-keychain send
   ```
2. Read the rules on chain:
   ```bash
   near contract call-function as-read-only cto.testnet get_config json-args '{}' network-config testnet now
   ```
   Expected: name `CTO`, symbol `CTO`, opening_price `1000000000000000000000000` (1,000,000 CTO), decay_delay_s `604800`, decay_length_s `604800`, faucet_amount `2000000000000000000000000`, takeover_ratio `7/5`, payout_ratio `23/28`.

> **Warning:** The next step is permanent. After it, nobody can change cto.testnet. Do it only if the `get_config` output in step 2 is correct.

3. Delete the temporary key and rename its file:
   ```bash
   near account delete-keys cto.testnet \
     public-keys "$(jq -r .public_key ~/.near-credentials/testnet/cto.testnet.json)" \
     network-config testnet sign-with-legacy-keychain send
   mv ~/.near-credentials/testnet/cto.testnet.json ~/.near-credentials/testnet/cto.testnet.deleted-key.json
   ```
4. List the keys:
   ```bash
   near account list-keys cto.testnet network-config testnet now
   ```
   Expected: no keys.

## 5. Seed the story on the main coin

1. Claim the faucet for ani and budi (2,000,000 CTO each). The first claim also registers storage.
   ```bash
   for a in ani-cto.testnet budi-cto.testnet; do
     near contract call-function as-transaction cto.testnet claim_faucet json-args '{}' \
       prepaid-gas '30 Tgas' attached-deposit '0.00125 NEAR' \
       sign-as $a network-config testnet sign-with-legacy-keychain send
   done
   ```
2. Make ani's voice key for the main coin. The key stays on your machine. Keep the file.
   ```bash
   mkdir -p ~/.cto-keys/ani-main
   near account create-account fund-later use-auto-generation save-to-folder ~/.cto-keys/ani-main
   mv ~/.cto-keys/ani-main/*.json ~/.cto-keys/ani-main.json
   export ANI_VOICE=$(jq -r .public_key ~/.cto-keys/ani-main.json)
   ```
3. As ani, take the empty seat for 1,000,000 CTO with face #2626 (batik / laser / grin / CEO tie):
   ```bash
   near contract call-function as-transaction cto.testnet take_seat \
     json-args "{\"face\":{\"bg\":5,\"eyes\":1,\"mouth\":0,\"extra\":1},\"new_ceo_key\":\"$ANI_VOICE\",\"max_price\":\"1000000000000000000000000\"}" \
     prepaid-gas '100 Tgas' attached-deposit '0.25 NEAR' \
     sign-as ani-cto.testnet network-config testnet sign-with-legacy-keychain send
   ```
4. Post line 1 as the coin. Sign with ani's voice key:
   ```bash
   near contract call-function as-transaction cto.testnet announce json-args '{"line":1}' \
     prepaid-gas '30 Tgas' attached-deposit '0 NEAR' \
     sign-as cto.testnet network-config testnet sign-with-access-key-file ~/.cto-keys/ani-main.json send
   ```
   Expected: the announcement reads "The face is mine until someone pays 1,400,000 CTO."
5. List the keys:
   ```bash
   near account list-keys cto.testnet network-config testnet now
   ```
   Expected: exactly one key. It is ani's voice key, and it can only call `announce`.

> **Note:** Stop after step 5. Budi's takeover (face #672, `{"bg":1,"eyes":2,"mouth":3,"extra":7}`) is for the video.

## 6. Record the proof

1. Run the checks and write the output to `web/public/verify.txt` and `README.md`:
   ```bash
   npm run verify -- --out web/public/verify.txt --readme
   ```
   Expected: 12 PASS.
2. Commit and push the output. Vercel redeploys, and Receipts shows the new output.
   ```bash
   git add web/public/verify.txt README.md && git commit -m "Verify output after deploy" && git push
   ```
3. Run the end-to-end tests against the deployed app:
   ```bash
   E2E_BASE_URL=https://ctotimes.xyz npm run test:e2e
   ```
4. Start the testnet end-to-end run in CI:
   ```bash
   gh workflow run ci.yml -f e2e_base_url=https://ctotimes.xyz
   ```
