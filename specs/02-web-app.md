# Spec 2: Web app (`web/`)

A static React app with four screens matching `../mockups/` and `../docs/DESIGN.md`. It reads everything from the contract with view calls and never invents a number. It opens on the demo coin so a judge can run the whole story without a wallet.

## Stack

| Part | Choice |
| --- | --- |
| App | Vite + React + TypeScript, React Router, Tailwind with the DESIGN.md tokens |
| Chain | `near-api-js` (JSON-RPC to testnet), `@near-wallet-selector` with MyNearWallet and Meteor |
| Motion | CSS keyframes as in the mockups; Framer Motion allowed only for the takeover sequence |
| Faces | `src/lib/faces.ts`, generated by a script from `reference/faces/faces.py`; a test compares it with the contract's `face_svg` |
| Hosting | Vercel; the relayer (spec 3) lives in the same project under `api/` |

## Routes and data

| Route | Screen | Mockup | Reads | Refresh |
| --- | --- | --- | --- | --- |
| `/` | Front page | `1-front-page.html` | `get_seat`, `ft_total_supply`, `get_history(0,8)`, `get_announcements(3)` | every 3 s |
| `/takeover` | Takeover desk | `2-takeover-desk.html`, `2b-takeover-sequence.html` | `get_seat`, caller's `ft_balance_of` | every 3 s; price frozen while confirming |
| `/press` | Press office | `3-press-office.html` | `get_seat`, `get_announcements(20)`, `get_lines`, latest takeover from `get_history` | every 3 s |
| `/receipts` | Receipts | `4-receipts.html` | `get_config`, RPC `view_access_key_list`, RPC `view_account` code hash, `get_history(0,50)`, `/sim/*.csv` | on load |

Every route takes `?coin=demo` (default → `demo-cto.testnet`) or `?coin=main` (`cto.testnet`); a masthead switch flips it. Explorer tx links: `https://testnet.nearblocks.io/txns/{hash}`. Account names and numbers come from `reference/constants.json` (copy into `web/src/config.ts` at build time) and from views.

## Two ways to act

| | Demo mode (default) | Wallet mode |
| --- | --- | --- |
| Who signs | The relayer, as ani or budi ("Play as" chips) | The user's wallet |
| Getting CTO | Seeded on the demo coin | "Claim 2,000,000 CTO" button → `claim_faucet` |
| Take the seat | `POST /api/demo/take-seat` | Wallet signs `take_seat` with 0.25 NEAR and `max_price` = the price on screen |
| Voice key | Relayer derives ani's and budi's | Made in the browser (below) |
| Post as the coin | `POST /api/demo/announce` with one of 6 demo lines | Browser signs `announce` as the coin's account, any of the 24 lines |

**Voice key in wallet mode** (the NEAR-only part):

1. Before `take_seat`, the browser makes an ed25519 key pair and sends only the public key as `new_ceo_key`.
2. The private key is saved in `localStorage` under `cto:voice:{contract}:{account}` and offered as a download `cto-voice-key.json`, with the warning "Lose this and you can't post as the coin until someone takes the seat."
3. To post, the app signs a transaction with signer = the coin's account and that key, calling `announce(line)`. No wallet pop-up.
4. If that key is no longer on chain, show the raw RPC error in the rejected panel, exactly as NEAR returned it.

## Screens

| --- | --- | --- | --- |
| Front page | Live face with CEO stamp, CEO name, "in office", seat price sticker, TAKE OVER, decay countdown + bar, payout/burn line, supply, burned, takeovers, 2–3 press releases, Hall of Fame with "#N YOU?" slot | Vacant seat ("Seat open: 1,000,000 CTO", no CEO stamp); decaying (bar red, "price dropping") | Ticker, face bob, stamp thunk, count-ups, live countdown, button wiggle, slot pulse |
| Takeover desk | Face preview + face number, 4 part tabs × 8 swatches, Shuffle, deal memo (you pay / to old CEO / burned / 0.25 NEAR), Play as or Connect wallet, TAKE THE SEAT | Not enough CTO (disabled, "you have X, need Y"); already CEO; price moved (new price, "Try again") | Swatch hover, card shuffle (never slot reels), memo bar fill |
| Takeover sequence | FIRED! on old face, new face drops, BREAKING headline, payout card, burn counter, tx chip, "Go to the press office" | Chain error: stop and show it | ≈ 4 s, starts only after the transaction succeeds |
| Press office | Breaking banner, **line picker** (24 lines from `get_lines`, slots previewed with live numbers), SIGN AS THE COIN, "Who holds the pen" key cards, ex-CEO panel with "Try posting as {ex-CEO}" | You are CEO; you are an ex-CEO; you never held the seat | Ex-CEO try: "Sending to NEAR…", then REJECTED stamp + shake from the real error; payout count-up |
| Receipts | Step list with tx links, verify output (from latest CI run), no-owner-keys list read live, 60-day chart with busy / quiet / abandoned tabs, main vs demo config | Calm page: no stickers on numbers | Steps check in, terminal types, chart draws, VERIFIED stamp |

Note: the press-office mockup shows a free-text composer; it predates the fixed-lines decision. Build a line picker instead.

**The wow moment is real, not a replay.** In demo mode "Try posting as ani" asks the relayer to sign `announce(3)` with ani's latest (now deleted) key; the REJECTED stamp lands only when NEAR's `AccessKeyNotFound` comes back, and that error text is printed unedited.

## Rules for every screen

- Numbers in JetBrains Mono, tabular figures, `1,400,000`; never "1.4M" except in the ticker.
- Footer: "Testnet only · no sale · no admin keys · open source".
- `prefers-reduced-motion`: no animation; numbers still update.
- Phone (375 px): one column, face first, sticky bottom bar with seat price + TAKE OVER, targets ≥ 44 px.
- No casino cues.

## Build notes (added Nov 11 while implementing)

- **Run it locally:** `npm run dev:chain` (sandbox with both coins, ani and budi; writes the git-ignored `web/.env.local`), then `npm run dev`. The Vite dev server serves the real `api/demo/*.ts` handlers, so demo mode works end to end. `vercel.json` routes everything but `/api` to the app.
- **Config:** `web/src/lib/reference.ts` (generated from `reference/*.json` by `scripts/gen-reference.mjs`) plays the role of `src/config.ts` data; `src/config.ts` derives from it. `VITE_*` overrides exist only for the local sandbox.
- **Faces** render as `<img src="data:image/svg+xml,...">` so the fixed pattern ids (`kw`, `pr`) never collide between faces on one page. `faces.ts` is generated by `scripts/gen-faces.py`, which calls faces.py's own part functions.
- **Explorer links.** The contract cannot know tx hashes, so a link comes from (1) hashes this browser saw (relayer and wallet replies, saved in localStorage), else (2) a match in nearblocks' `/v3/accounts/{coin}/txns` (a `take_seat` by that CEO at or just before the takeover's `block_height`; an `announce` within 6 s of `at_ns`), else (3) the coin's account page. Never a made-up hash. `/announce` now also returns `announcementIndex` for (1).
- **Demo mode** exists only on the demo coin; the default "Play as" is whoever is not CEO (ani when vacant). In the press office, demo posting always uses the current CEO's key if the CEO is ani or budi, with the six demo lines; wallet mode offers all 24.
- **Wallet mode:** the wallet modules (and their Buffer/global shims) load only on connect or a saved session. MyNearWallet redirects; the pending action is kept in sessionStorage and finished from `?transactionHashes=` on return. A voice key file can be loaded back in ("Load your cto-voice-key.json") for the second-browser check.
- **Front page** "Launch notice" is fixed copy shown under fewer than 3 posts, with the deploy tx link but no "SIGNED BY" chip (it was never an on-chain post).
- **Receipts** runs the keyless checks in the browser (keys, supply = total − Σ burned, icon = `face_svg`, this page's faces = chain's, code hash if `/build-info.json` exists) and shows `/verify.txt` as the latest CI output when present (both produced in specs 4 and 6). The VERIFIED stamp appears only when every browser check passes. Steps come from `get_history` and `get_announcements`.
- **Motion:** the mockups' `pulse` keyframes collided with Tailwind v4's own `pulse` (an opacity fade), so ours is `cto-pulse`. Reduced motion sets `animation: none` everywhere.
